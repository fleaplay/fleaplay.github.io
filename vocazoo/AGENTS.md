# 보카주 정책 문서의 시행 안내

이 지침은 `vocazoo/` 아래 개인정보 처리방침과 이용약관을 수정할 때 적용한다.

- `policy/index.html`과 `terms/index.html`은 서비스와 상세페이지에서 사용하는 고정 주소다. 기존 연결을 유지한다.
- 사용자는 이전 버전 조회를 원하지 않는다. 공개 변경 이력, 이전 원문 링크, 날짜별 보관 페이지를 만들지 않는다. 변경 기록은 Git으로 관리한다.
- 시행일이 미래인 문서는 공고일과 시행일을 명확하게 표시해 미리 안내한다. 최초 시행일은 `2026-11-01`이다.
- 저장소 루트의 `js/policy-schedule.js`가 브라우저의 현재 시각을 한국 시간(Asia/Seoul)으로 비교해 공지와 적용 문서를 선택한다. 문서를 열거나 한국 시간 자정을 지나면 다시 선택하고, 탭으로 돌아올 때도 확인한다. JavaScript를 끈 환경에서는 자동 전환하지 않으므로 `noscript` 안내를 유지한다.
- 현행 문서는 `[data-policy-content]` 안의 `article.policy-document`에 둔다. `data-policy-effective-on`, `data-policy-announced-on`은 `YYYY-MM-DD` 형식, `data-policy-change-summary`는 주요 변경 내용이다.
- 개정 예고 시에는 현행 본문을 유지하고, 같은 `[data-policy-content]` 안에 `<template data-policy-scheduled>`를 추가한다. 그 안에 새 `article.policy-document` 본문과 새 공고일·시행일·변경 요약을 작성한다. 예정 원문은 별도 공개 URL로 만들지 않는다. 문서 ID는 중복되지 않도록 template 안에서는 생략한다.
- 공고일 전에는 예정 문서를 표시하지 않는다. 공고일부터 시행일 전까지는 현행 문서와 예정 안내를 표시하고, 안내의 버튼으로 예정 본문을 미리 볼 수 있다. 시행일에는 예정 문서가 현행 문서로 자동 전환되고 이전 버전은 화면에서 제거된다. 최초 시행 전처럼 현행 문서가 없으면 예정 본문을 사전 안내로 표시한다.
- 시행일 후 다음 소스 정리 시 적용된 본문을 일반 article로 옮기고 오래된 본문과 적용이 끝난 template을 제거한다. 이전 문서로 돌아가는 버튼이나 날짜·쿼리로 과거 버전을 고르는 기능을 만들지 않는다.
- 시행일이 정해지지 않은 개정 문서의 날짜를 임의로 정하지 않는다.
- 개인정보 처리방침과 이용약관의 공고일·시행일, 본문 안내, 메타 설명을 일치시킨다.
- 수정 후 상세페이지의 연결, 정책 페이지 간 이동, 이미지 경로 및 시행일을 확인한다.
